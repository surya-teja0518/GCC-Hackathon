The Solution

Autonomous Loop: Detect → Diagnose → Act

Agentic Workflow

1. Detect: Continuous telemetry polling of pg_stat_activity, pg_locks, & pg_stat_database.
2. Diagnose: Retrieves wait-event RAG knowledge + invokes Claude Sonnet 5 via Azure AI Foundry.
3. Act: Raises incident ticket (INC-00458) with pre-formulated, copyable SQL remediation scripts.

🛡 Safety Guardrail: "generates SQL for a human to run — nothing executes automatically."
SPEAKER SCRIPT (45s):
"dbpulse continuously watches PostgreSQL telemetry. When an anomaly occurs, it retrieves domain troubleshooting guidance via RAG, invokes Claude Sonnet 5 on Azure AI Foundry to explain the root cause, and drafts an incident ticket with exact remediation SQL. Crucially, we follow a strict safety guardrail: dbpulse generates SQL for a human DBA to execute — nothing mutates production databases automatically."

Architecture

Azure Stack & Lean Engineering

Backend & Database
  • Python Flask REST API (Single-process server).
  • Azure Database for PostgreSQL (Flexible Server).
  • Queries pg_stat_activity & pg_locks.
AI Reasoning & Fallback
  • Azure AI Foundry (Claude Sonnet 5 / gpt-5.4-mini).
  • PostgreSQL Wait-Event RAG Knowledge Base.
  • Built-in deterministic fallback engine for 100% demo uptime.
